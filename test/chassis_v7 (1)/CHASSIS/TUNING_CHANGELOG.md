## 修改 #2 — 2026-05-28 08:55

### 修改原因
经分析，FF前馈对本系统用处不大，反而增加调参复杂度：
1. 左右FF不同本身就引入偏差，需要PI额外补偿
2. FF是固定值，不能自适应工况变化
3. 增量式PID的积分项本质上就是"自适应FF"，会自动找到稳定运行所需的PWM基线
4. 已有的 start boost 机制覆盖了启动阶段的需要

决定切换为WHEELTEC风格的纯PI控制（无FF），减少调参复杂度。

### 修改前参数（修改#1的结果）
| 参数 | 值 |
|------|-----|
| `SPEED_PID_DEFAULT_KP` | 60.0 |
| `SPEED_PID_DEFAULT_KI` | 1.5 |
| `MOTOR_LEFT_FF_DEFAULT` | 1450 |
| `MOTOR_RIGHT_FF_DEFAULT` | 1450 |

### 修改后参数
| 参数 | 值 | 修改理由 |
|------|-----|----------|
| `SPEED_PID_DEFAULT_KP` | **15.0** | 对齐WHEELTEC参考值 |
| `SPEED_PID_DEFAULT_KI` | **7.0** | 对齐WHEELTEC参考值，积分项自动充当FF |
| `MOTOR_LEFT_FF_DEFAULT` | **0** | 去掉FF前馈 |
| `MOTOR_RIGHT_FF_DEFAULT` | **0** | 去掉FF前馈 |
| `MOTOR_PWM_MIN_EFFECTIVE` | **0** | FF=0后此值也设为0 |

### 保留未改的参数
| 参数 | 值 | 保留理由 |
|------|-----|----------|
| `MOTOR_START_BOOST_MS` | 250 | start boost保留，帮助启动过渡 |
| `MOTOR_LEFT_START_BOOST_PWM` | 2100 | 克服静摩擦仍需要 |
| `MOTOR_RIGHT_START_BOOST_PWM` | 2000 | 克服静摩擦仍需要 |

### 架构变化说明
```
修改前: 最终PWM = PI修正量 + FF前馈(1450) + start_boost
修改后: 最终PWM = PI输出(自动累积到合适基线) + start_boost

PI积分累积过程（target=5, 电机从静止开始）:
  第1个10ms: output = 15×5 + 7×5 = 110
  第2个10ms: output += 0 + 35 = 145
  ...
  约0.4秒后: output ≈ 1500 （自动达到原FF值的水平）
  start_boost在前250ms提供2000+的PWM，覆盖了这个过渡期。
```

### 代码安全检查
- `limit_pwm_command()`: FF=0时min_eff=0，`mag>0 && mag<0`为false，开环模式正常
- `add_speed_feedforward()`: start_pwm=0，输出等于pid_pwm，无影响
- `apply_start_boost()`: 不依赖FF，正常工作

### 测试结果
> 架空测试：右电机转，左电机没反应。
> 原因分析见修改#3。

## 修改 #3 — 2026-05-28 09:03

### 修改原因
修改#2测试发现：右电机转，左电机没反应（启停振荡）。

**根因：Start Boost与纯PI（FF=0）冲突**

问题链条：
1. Start Boost强制PWM=2100，持续250ms
2. 2100 PWM让电机速度远超目标值（目标=8，实际可能=20+）
3. 增量式PI看到"超速"，疯狂减修正量，PI输出变成大负数（-500~-1000）
4. 250ms后Boost结束，PI输出是负的
5. `add_speed_feedforward()`将负输出钳位到0（因为target>0时不允许反转）
6. 电机PWM=0，停转
7. PI慢慢从负值恢复到正值，需要14~20个tick（140~200ms）
8. 恢复后电机又启动 → 但没有Boost了，PI从0开始爬升
9. 左电机摩擦更大，PI爬到能转的值需要更久 → 看起来"没反应"

**解决方案：禁用Start Boost，让PI自然爬升**

WHEELTEC示例本身就没有Start Boost。纯PI控制下：
- PI从0开始，每10ms累积约56（KI×target=7×8）
- 约0.3秒后PI输出达到1500，电机开始转
- 0.3秒的启动延迟完全可接受

### 修改内容
| 参数 | 修改前 | 修改后 | 理由 |
|------|--------|--------|------|
| `MOTOR_START_BOOST_MS` | 250 | **0** | 禁用Boost，避免与PI冲突 |
| `MOTOR_LEFT_START_BOOST_PWM` | 2100 | **0** | 配套禁用 |
| `MOTOR_RIGHT_START_BOOST_PWM` | 2000 | **0** | 配套禁用 |
| `MOTOR_PWM_RAMP_STEP` | 60 | **120** | 加快PWM爬升，补偿无Boost的启动延迟 |

### 当前完整参数汇总
```c
// PID参数（WHEELTEC风格纯PI）
SPEED_PID_DEFAULT_KP = 15.0
SPEED_PID_DEFAULT_KI = 7.0

// 前馈（已禁用）
MOTOR_LEFT_FF_DEFAULT = 0
MOTOR_RIGHT_FF_DEFAULT = 0

// Start Boost（已禁用）
MOTOR_START_BOOST_MS = 0
MOTOR_LEFT_START_BOOST_PWM = 0
MOTOR_RIGHT_START_BOOST_PWM = 0

// PWM爬升步长
MOTOR_PWM_RAMP_STEP = 120
```

### 测试结果
> 架空测试：右电机转，左电机不转。
> 原因分析见修改#4。

## 修改 #4 — 2026-05-28 09:12

### 修改原因
修改#3测试发现：左侧电机彻底死机不转。

**根因分析：参数水土不服 + 震动干扰**
1. **编码器分辨率差异**：WHEELTEC原版目标速度是30~50级别，KP=15能产生450+的PWM。本车MG513电机目标速度仅为8，KP=15时比例输出仅120，驱动力极其微弱。
2. **震动导致积分被误清**：因为没有FF前馈，左电机需要漫长的时间（约0.4秒）靠积分爬升到1500以上的启动阈值。但由于右电机摩擦小先转了起来，底盘震动导致悬空的左电机编码器读到了微小的跳动数值（假信号）。PID算法误以为左轮已启动，立刻减小输出，导致左轮PWM永远卡在无法启动的低电平。

**解决方案：高阶混合架构（强比例 + 保守统一FF + 积分补偿）**
不能照搬WHEELTEC的参数。恢复适合本车的强力KP，并给一个安全的、相同的“底线”FF（1300），让电机瞬间跨越漫长的积分死区，避免震动干扰，剩下的细微跑偏交给KI去自动抹平。

### 修改内容
| 参数 | 修改前 | 修改后 | 理由 |
|------|--------|--------|------|
| `SPEED_PID_DEFAULT_KP` | 15.0 | **60.0** | 恢复适合本车编码器分辨率的比例力度 |
| `SPEED_PID_DEFAULT_KI` | 7.0 | **3.0** | 提供温和的稳态误差补偿 |
| `MOTOR_LEFT_FF_DEFAULT` | 0 | **1300** | 恢复统一的保守前馈，瞬间跨越电机死区 |
| `MOTOR_RIGHT_FF_DEFAULT` | 0 | **1300** | 统一前馈，避免人为制造左右差异 |

### 预期效果
- 启动瞬间，PWM = FF(1300) + KP(60×8=480) = 1780，两轮将**瞬间同时启动**，不会再有死机现象。
- 行驶过程中，由于FF相同（都是1300），如果左侧摩擦力大导致速度慢，KI=3.0的积分项会自动把左侧PWM慢慢推高（比如推到1850），从而实现直线行驶不跑偏。

### 测试结果
> 架空测试：两轮瞬间同时启动，不会再卡死，且编码器数值显示非常稳定。
> 地面测试：FF=1300动力不足，用户手动调整至FF=1800后正常起步行驶。

## 修改 #5 — 2026-05-28 09:30

### 修改原因
地面带载测试结果：加上车身自重和履带接地摩擦力后，FF=1300 无法让小车起步。手动调到 1800 后小车可以正常行驶。
**关于“走着走着还是偏”的诊断：**
这是**物理现象，不是速度环有BUG，而是确实缺少方位环（陀螺仪角速度环）**。
1. 速度环的作用仅仅是保证“左轮的转动圈数 = 右轮的转动圈数”（即编码器脉冲数相等）。
2. 但履带车在地面行驶时存在**打滑现象**。左轮转10圈和右轮转10圈，由于左右侧重心分布不均、地面摩擦系数细微差异，实际在地面走过的物理距离是不一样的。
3. 起步瞬间如果右轮比左轮早动0.1秒，车头就会歪出一个角度。**纯速度环不知道车头歪了**，它只会继续保持两轮转速相等，于是小车就会沿着歪掉的方向一直走直线（跑偏）。

### 修改内容
| 参数 | 修改前 | 修改后 | 理由 |
|------|--------|--------|------|
| `MOTOR_LEFT_FF_DEFAULT` | 1300 | **1800** | 匹配地面行驶的实际静摩擦力 |
| `MOTOR_RIGHT_FF_DEFAULT` | 1300 | **1800** | 统一调整 |
| `MOTOR_PWM_MIN_EFFECTIVE` | 1300 | **1800** | 同步更新有效底线 |

### 下一步建议
如果追求绝对的走直线，必须引入**陀螺仪（如MPU6050）建立转向环/方位环**。利用Z轴偏航角计算出车头偏转偏差，动态给左右轮的速度目标加上一个补偿值（左侧加速、右侧减速）来强制把车头拉正。
